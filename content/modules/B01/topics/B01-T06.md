## 考查目标
区分进程与线程，解释状态转换，并计算 FCFS、SJF、优先级和 Round Robin 的调度指标。

## 必要概念
进程是资源拥有与隔离的运行实例，线程是 CPU 调度执行流；同进程线程通常共享地址空间和打开文件，各自拥有栈、寄存器上下文。基本状态为 ready、running、blocked。等待 I/O 会从 running 到 blocked；I/O 完成进入 ready，而不是直接保证 running。

## 原理与条件
周转时间=完成时间−到达时间；等待时间=周转时间−CPU burst（若无额外阻塞模型）；响应时间=首次运行时间−到达时间。FCFS 简单但可能产生 convoy effect；非抢占 SJF 在已知 burst 时优化平均等待；SRTF 是抢占版本；RR 用时间片改善交互响应，但过小会增加切换开销。优先级调度可能 starvation，aging 可逐步提高等待任务优先级。

## 推导例题
三个任务同时到达，burst 为 6、2、4。FCFS 顺序 P1,P2,P3 的等待为 0、6、8，平均 14/3；SJF 顺序 P2,P3,P1 的等待为 0、2、6，平均 8/3。SJF 优势依赖 burst 可知且同时到达的模型。

调度分不同层次：long-term/job scheduler 决定哪些作业进入内存和 ready 集合，影响 multiprogramming degree；short-term/CPU scheduler 从 ready 队列选择下一执行者；medium-term scheduler 可换出/换入进程。操作系统配置应区分 boot loader、kernel、driver、service 与 user application：驱动或内核参数变更可能需要重启，普通进程配置通常不需要重建内核，具体生效方式仍服从目标系统文档。

## 易错点与反例
- blocked 任务不是在等 CPU，不能被调度器直接选中。
- context switch 有保存/恢复成本，本身不完成用户工作。
- 多线程提升并发性，但在单核 CPU-bound 场景不保证缩短总 CPU 时间。

## 自查
到达 2、首次运行 5、完成 11、CPU burst 6，则响应时间 3、周转 9、等待 3。

## 关联练习
练习要求画时间线并分别计算完成、等待、响应，避免混用指标。
