## 考查目标
按输入输出区分词法分析、语法分析、语义分析、中间代码生成、优化与目标代码生成，并能把短程序切成 token。

## 必要概念
词法分析把字符流分组为 token，常见类别有关键字、标识符、字面量、运算符和分隔符；空白与注释通常被过滤，但位置信息会保留。token 的类别与属性分开，例如标识符 token 携带词素或符号表入口。正则表达式和有限自动机适合描述多数 token 类。

## 原理与条件
词法器处理局部字符模式，解析器依据上下文无关文法处理 token 结构。类型不匹配、未声明标识符通常属于语义分析，而不是词法错误。典型管线为：源字符→token→语法树/AST→带类型和绑定信息的 AST→中间表示→优化 IR→目标代码。真实编译器可合并阶段，但题目考查的是职责而非进程数量。

## 推导例题
输入 `sum += 12;` 可分为 `IDENT(sum)`、`PLUS_ASSIGN`、`INT_LITERAL(12)`、`SEMI`。最长匹配使 `+=` 成为一个 token，而非 `+` 与 `=` 两个 token。随后解析器确认它符合赋值表达式结构；语义阶段再检查 `sum` 是否已声明且可修改。

## 易错点与反例
把关键字识别成标识符再查表是可行实现策略，不改变最终 token 类别。`x + * 3` 中每个字符都能形成合法 token，但组合不符合表达式文法，所以是语法错误。`x + true` 可能语法正确而类型错误。优化不能改变可观察语义。
