## 考查目标
以 PostgreSQL 18 方言正确使用 IN、EXISTS、相关子查询及数据更新，并处理 NULL 与多行子查询边界。

## 必要概念
非相关子查询可独立计算；相关子查询引用外层当前行。`EXISTS` 只判断是否存在行。标量子查询必须至多一行。`NOT IN` 遇到子查询结果含 NULL 会产生 UNKNOWN，反连接通常用 `NOT EXISTS` 更稳妥。

## 原理与条件
更新语句同样受约束与事务保护。基于另一表更新时要保证每个目标行匹配至多一个来源事实，避免结果不确定。删除父表前先考虑外键动作与历史保留策略。

## 推导例题
PostgreSQL 18：找从未选课的学生：`SELECT s.student_id FROM student s WHERE NOT EXISTS (SELECT 1 FROM enrollment e WHERE e.student_id=s.student_id);`。相关条件把当前学生带入内层；即使 Enrollment.student_id 意外允许 NULL，也不影响结论。`NOT IN (SELECT student_id ...)` 则可能因一个 NULL 使所有比较都不是 TRUE。


### 数据库访问与参数化

SQL 描述数据操作；应用程序还需要连接、执行、取回结果、处理错误并结束事务。ODBC 是通用访问接口，JDBC 是 Java 接口体系；C 程序可用数据库厂商提供的客户端库，例如 PostgreSQL 的 libpq。接口调用与 SQL 语义是两层概念。

把用户输入拼进 SQL 会混淆“数据”与“命令”。例如查询账号时，应该使用 `WHERE account = $1` 并通过参数数组传值；输入中的引号应作为数据处理。值参数不能替代任意表名或排序关键字，动态标识符应从允许的集合选择。参数化也不能代替业务授权：即使查询安全，用户仍不能读取无权访问的记录。

一次转账需要在同一事务内扣款和入账，先检查余额及更新是否成功，再提交；任一步失败应回滚。连接池归还连接前必须清理未完成事务，避免下一位使用者继承错误状态。

## 易错点与反例
`= (subquery)` 返回多行会报错；需要集合成员关系时用 IN。`UPDATE` 没有 WHERE 会更新所有行。先 SELECT 预览不能替代事务和约束，但能降低操作错误。

## 自查
对 NOT IN 主动问：子查询列能否为 NULL？对标量子查询问：唯一约束是否保证至多一行？

练习覆盖相关/非相关子查询、NULL、更新与约束失败。
