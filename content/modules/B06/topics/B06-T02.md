# C++对象生命周期与资源管理

> 代码基线：C++17；UML 记法按 UML 2.5.1。后续版本特性会明确标注，本节不依赖未指定行为。

## 考查目标

能够准确识别C++对象生命周期与资源管理中的角色、约束与边界；能从题干材料推导唯一结论，并说明结论成立的前提。

## 必要概念

C++17 对象生命周期从初始化完成开始，到析构开始或存储被复用时结束。构造顺序是虚基类、直接基类、按声明顺序的数据成员、构造函数体；析构严格逆序。RAII 把资源获取放入对象初始化，把释放放入析构，因此正常返回与异常展开共享清理路径。优先使用值成员、std::vector、std::string、std::unique_ptr；只有共享所有权才使用 std::shared_ptr。Rule of Zero 表示让资源类成员承担管理，从而不手写特殊成员；直接管理裸资源时必须考虑复制、移动、赋值和析构的一致性。

## 原理与条件

完整对象的构造顺序由声明决定：虚基类、直接基类、数据成员声明顺序、构造函数体；析构反向进行。初始化列表写成 `y(2), x(1)` 也不会改变先声明的 x 先构造。若成员构造抛异常，完整构造的更早成员与基类会逆序清理，而最外层对象从未完成构造，因此其析构函数不执行。

RAII 要求资源句柄和释放动作同属一个对象。`unique_ptr` 表示独占，`shared_ptr` 表示共同延长生命周期，`weak_ptr` 表示不拥有的观察关系；“很多地方要访问”不等于共享所有权。资源类能由 string、vector、unique_ptr 等成员组合表达时采用 Rule of Zero；自行管理裸句柄时才需要系统设计复制、移动、赋值和析构。

## 推导例题

struct Trace 的构造与析构打印名字；struct Base 含 Trace b；struct Derived: Base 含 Trace d。执行 { Derived x; } 时顺序是 Base 构造开始前先构造 b，然后 Base 函数体，再构造 d，再 Derived 函数体；离开块时逆序：Derived 函数体对应的析构体、d、Base 析构体、b。成员初始化列表书写次序不会改变按声明顺序初始化这一规则。将文件句柄包入 unique_ptr 自定义删除器后，后续 vector::push_back 抛出异常也不会漏关句柄。

对 Trace 例先写构造事件 `b, Base-body, d, Derived-body`，再严格反转已经完成的子对象得到析构事件。对异常路径则在抛出点画界线，只反转界线之前已完成构造的对象。

## 易错点与反例

1. 按初始化列表书写顺序推演成员构造；标准规定成员按声明顺序。
2. 为“保险”无条件使用 shared_ptr；这会隐藏真正所有者，并可能形成强引用环。
3. 在 C++ 输出题中忽略对象切片、析构顺序、异常展开或迭代器失效。若片段含未定义行为，就不能声称有确定输出。
4. 看到包装结构就一律回答装饰器。必须以转换接口、增加职责或控制访问的意图区分适配器、装饰器和代理。
