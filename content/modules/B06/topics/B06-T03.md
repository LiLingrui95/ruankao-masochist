# 继承、虚函数与多态

> 代码基线：C++17；UML 记法按 UML 2.5.1。后续版本特性会明确标注，本节不依赖未指定行为。

## 考查目标

能够准确识别继承、虚函数与多态中的角色、约束与边界；能从题干材料推导唯一结论，并说明结论成立的前提。

## 必要概念

继承表达 is-a 替换关系；组合表达 has-a，通常更适合复用实现。基类虚函数经基类指针或引用调用时按动态类型分派；按值传参会切片并丢失派生部分。override 让编译器检查签名是否真正覆盖。若对象可能经基类指针删除，基类析构函数必须是 public virtual；若禁止这种删除，可用 protected non-virtual。构造和析构期间的虚调用只分派到当前正在构造或析构的层次，不会调用尚未存在或已销毁的派生部分。

## 原理与条件

虚调用要同时标出表达式的静态类型、对象的动态类型和函数是否真正覆盖。`Base& r=d; r.f()` 只有在 Base::f 为 virtual 且 Derived 签名匹配时才到派生实现；`r.Base::f()` 用限定名抑制虚分派。`override` 会把漏写 const、参数不同等“以为覆盖”变成编译错误。按值接收 Base 会构造 Base 副本并切片，副本动态类型就是 Base。

构造 Base 子对象期间，Derived 部分尚未开始生命周期，虚调用只到 Base 的最终覆盖者；析构到 Base 阶段时 Derived 部分已经销毁，同理不会回调 Derived。多态基类若允许经 Base* 删除必须有 public virtual 析构；否则 `delete basePointer` 指向派生对象是未定义行为，不能编造确定输出。

## 推导例题

Shape 定义 virtual double area() const=0 与 virtual ~Shape()=default；Circle 覆盖 area。sum(const vector<unique_ptr<Shape>>& xs) 对每个元素调用 area，保留动态多态。若改成 vector<Shape> 既因抽象类不可实例化而不成立；对非抽象基类按值存储则会切片。若 Circle::area 漏掉 const，override 会使程序在编译期报错，而不是悄悄形成重载。

Shape 例中先检查 `area() const` 的签名完全一致，再沿 `unique_ptr<Shape>` 的虚调用选择 Circle::area，最后沿虚析构链先销毁 Circle 后销毁 Shape。若把容器改为按值 Base，必须先判断是否可实例化，再讨论切片。

## 易错点与反例

1. 认为同名函数必然覆盖；参数、cv/ref 限定不一致可能只是隐藏或重载。
2. 给基类添加普通析构后继续通过 Base* 删除派生对象；非虚析构并不能形成多态销毁。
3. 在 C++ 输出题中忽略对象切片、析构顺序、异常展开或迭代器失效。若片段含未定义行为，就不能声称有确定输出。
4. 看到包装结构就一律回答装饰器。必须以转换接口、增加职责或控制访问的意图区分适配器、装饰器和代理。
