# C++模板、容器与异常

> 代码基线：C++17；UML 记法按 UML 2.5.1。后续版本特性会明确标注，本节不依赖未指定行为。

## 考查目标

能够准确识别C++模板、容器与异常中的角色、约束与边界；能从题干材料推导唯一结论，并说明结论成立的前提。

## 必要概念

模板把算法对类型的依赖变成参数；实例化要求实参满足模板体实际使用的操作。标准容器负责元素存储与生命周期，vector 连续存储且扩容可能使迭代器、指针和引用失效。异常沿调用栈寻找匹配处理器，展开期间已完整构造的自动对象被析构。基本保证要求失败后对象仍有效且无资源泄漏；强保证要求失败如同未发生；不抛保证常用于析构与交换。按 const 引用捕获多态异常可避免复制和切片，处理器从前到后匹配，因此派生异常应写在基类异常之前。

## 原理与条件

阅读模板先把模板体中的表达式列为类型要求：`*first` 要求可解引用，`best < value` 要求可比较，赋值要求结果可赋给 T。C++17 不会仅因写了 `template<class T>` 就保证所有类型可用。vector 重新分配后，指向旧元素的迭代器、指针和引用全部失效；使用前必须依据具体操作和容量变化判断有效性。

异常处理器从前到后匹配，派生异常处理器应置于基类处理器之前，并按 const 引用捕获。栈展开只析构已经完整构造的自动对象。强异常保证常用“临时结果成功后交换/提交”实现；基本保证只承诺对象仍有效且无泄漏，并不承诺值不变。析构函数一般不得让异常逃逸。

## 推导例题

模板 max_value(first,last) 先检查空区间并抛 invalid_argument，再用 *first 初始化结果，循环比较更新。调用者在 try 中创建 vector<int> 与 Guard，空输入时异常离开函数，Guard 仍被析构。若 catch(const invalid_argument&) 在 catch(const exception&) 之前，能进行细分处理；相反顺序会让前者永远无法处理该异常。该例以 C++17 规则推演，不依赖未指定的实参求值次序。

max_value 例先检查空区间，在解引用前抛 invalid_argument；非空时写出模板所需的解引用、比较和赋值能力。异常路径按调用栈列出 Guard 的逆序析构，再选择第一个匹配处理器。

## 易错点与反例

1. 保存 vector 元素地址后无条件 push_back，再使用旧地址；若发生重新分配，旧地址已经失效。
2. 把 `catch(std::exception)` 放在派生异常前且按值捕获；前者先匹配，并发生异常对象切片。
3. 在 C++ 输出题中忽略对象切片、析构顺序、异常展开或迭代器失效。若片段含未定义行为，就不能声称有确定输出。
4. 看到包装结构就一律回答装饰器。必须以转换接口、增加职责或控制访问的意图区分适配器、装饰器和代理。
