# 创建型设计模式

> 代码基线：C++17；UML 记法按 UML 2.5.1。后续版本特性会明确标注，本节不依赖未指定行为。

## 考查目标

能够准确识别创建型设计模式中的角色、约束与边界；能从题干材料推导唯一结论，并说明结论成立的前提。

## 必要概念

创建型模式隔离对象创建的变化。工厂方法把一个产品的实例化延迟给子类或可覆盖工厂；抽象工厂一次提供一族相容产品；生成器分步构造复杂对象并可复用过程；单例控制唯一实例但会引入全局状态和测试耦合，不应作为默认容器。判断模式时先找变化点：若客户端应与具体产品解耦，工厂最直接；若产品必须成套切换，抽象工厂才有价值。

## 原理与条件

工厂方法通常由 Creator 定义创建点，ConcreteCreator 决定一种 Product；抽象工厂提供多个创建操作，ConcreteFactory 保证 Button、Menu 等产品来自相容族；生成器把固定装配过程与不同表示分开。先数“变化的是一个产品、整族产品还是构建步骤”，再选择模式，避免把任何返回对象的函数都叫抽象工厂。

C++ 工厂返回 `unique_ptr<AbstractProduct>` 时，抽象产品必须有虚析构，调用者获得清楚的独占所有权。单例仅解决实例访问与数量约束，却把依赖藏在全局入口；需要唯一配置实例时可在组合根创建一次，再以接口引用注入客户，从而保持可测试性。

## 推导例题

跨平台界面需要 Button 与 Checkbox 始终来自同一主题族。GUIFactory 声明 createButton/createCheckbox，LightFactory 与 DarkFactory 各自产生同族产品；Screen 只依赖 GUIFactory。这是抽象工厂。若只有 Parser 一种产品、子类决定 JsonParser 或 XmlParser，则工厂方法更小。C++ 返回 unique_ptr<Product> 明确独占所有权，抽象产品析构函数设为 virtual。

跨平台 GUI 例先列两个抽象产品 Button/Checkbox，再检查每个平台是否必须整族切换；因为客户一次需要多个相容产品，选择抽象工厂而非单一工厂方法，并由一个 ConcreteFactory 注入保证不混族。

## 易错点与反例

1. 只有一个产品却建立一整套抽象工厂族，增加无用层次。
2. 工厂返回裸指针但不说明释放者，导致产品所有权无法从接口判断。
3. 在 C++ 输出题中忽略对象切片、析构顺序、异常展开或迭代器失效。若片段含未定义行为，就不能声称有确定输出。
4. 看到包装结构就一律回答装饰器。必须以转换接口、增加职责或控制访问的意图区分适配器、装饰器和代理。
