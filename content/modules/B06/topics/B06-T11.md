# C++设计模式综合案例

> 代码基线：C++17；UML 记法按 UML 2.5.1。后续版本特性会明确标注，本节不依赖未指定行为。

## 考查目标

能够准确识别C++设计模式综合案例中的角色、约束与边界；能从题干材料推导唯一结论，并说明结论成立的前提。

## 必要概念

模式综合题先写问题中的稳定部分与变化点，再给模式意图、角色映射、对象所有权和关键调用。C++ 实现还必须检查抽象基类虚析构、unique_ptr/shared_ptr 的选择、异常边界和复制语义。多个模式协作时每个模式只解决一个问题：抽象工厂创建相容对象族，策略替换算法，装饰器叠加功能，观察者传播事件；不要为追求模式数量而重复包装。

## 原理与条件

综合程序题要同时核对模式职责和 C++ 机制。先找变化点，再映射 Context/Component/Invoker 等角色；随后检查抽象基类虚析构、unique_ptr 所有权、move 后对象状态和异常提交点。角色名正确但所有权模糊，仍不是完整设计。

三类典型执行模型要能手工展开：策略程序由 Context 经虚调用进入具体算法，异常回到业务边界；装饰链调用从外到内、返回值从内到外、析构沿 unique_ptr 链递归；命令程序先 execute，成功后才把命令移入历史，undo 操作同一 Receiver。题目只使用 C++17 中结果确定的代码。

## 推导例题

报表系统用 ReportFactory 创建 HtmlReport/PdfReport（工厂方法），ReportService 持有 unique_ptr<ExportStrategy> 选择文件或网络导出（策略），AuditReportDecorator 包装 Report 并附加审计页（装饰器）。Report 与 ExportStrategy 都有 virtual 析构；Service 独占策略，用 unique_ptr。exportReport 先生成内容再调用策略，网络异常在服务边界捕获并转换为业务错误。三种职责分别是创建、算法替换、附加表现，不重叠。

报表例把创建、导出算法和附加审计页分别交给工厂、策略、装饰器。继续检查每个抽象产品是否有虚析构、每个 unique_ptr 的唯一拥有者，以及 NetworkError 在服务边界转换后资源是否由 RAII 清理。

## 易错点与反例

1. 为同一变化点叠加多个模式，只因名称越多看似越完整，实际造成重复职责。
2. 在命令入历史后才调用 execute；一旦执行抛异常，失败命令会错误地留在可撤销历史中。
3. 在 C++ 输出题中忽略对象切片、析构顺序、异常展开或迭代器失效。若片段含未定义行为，就不能声称有确定输出。
4. 看到包装结构就一律回答装饰器。必须以转换接口、增加职责或控制访问的意图区分适配器、装饰器和代理。
