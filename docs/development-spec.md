# 软件设计师学习台开发规范

当前内容基线已更新为 [002 考试对标规格](../specs/002-exam-alignment/spec.md)：前三单元采用考试专题与综合推导练习，旧 CSF 内容归档。结果反馈必须同时使用符号、颜色和文字；正确为绿色 ✔、错误为红色 ❌、待自评为中性灰。原有数据保留与本地单用户范围继续适用。下文与 002 冲突时以 002 为准。

版本：1.1 · 日期：2026-09-24 · 状态：总体规范；前三单元与 P1 子集已实现，尚未经过用户试用。当前实现边界以 [001 spec](../specs/001-study-session/spec.md) 与 [verification](../specs/001-study-session/verification.md) 为准，不能把下述未来阶段需求视为已完成。

本文中的 MUST 是必须满足的要求；SHOULD 是默认采用、偏离时需记录理由的建议。具体开发任务必须引用需求编号与验收编号。

## 1. 用户、目标和假设

已确认：单一学习者；备考软件设计师；学过 Python、C#；只接触少量数据结构与算法；希望平台精简、愿意日常打开；采用 SDD 开发。

工作假设：电脑承担主要学习与案例作答；手机是后续补充；考试日期、每天可投入时间、Java/C++ 选考方向尚未确定。使用相对学习阶段，不预设考试倒计时，也不承诺固定天数通过考试。

目标是让用户完成“理解一个概念 → 独立作答 → 得到反馈 → 留下记录 → 间隔复习 → 确定下一步”。已有 Python/C# 经验用于解释概念，不等同于已经掌握操作系统、数据库、网络或软件工程。

建议先以 Java 作为面向对象考试方向的候选，因为用户接触过 C#；首次进入该方向前允许选择 Java 或 C++。C 基础单独学习，不能因为选 Java 而省略。选考规则实施前依据当期考试材料再次核验。

成功指标是产品试用目标，不是已经验证的结果：打开后 30 秒内开始一个任务；一键继续上次；每天额外记录操作不超过 1 分钟；一周内能自然完成至少 3 次短学习。达不到时先检查任务难度、内容清晰度与操作数量。

## 2. 产品原则与范围

| ID | 规范 |
| --- | --- |
| PR-01 | MUST 先讲必要概念，再练对应题；不以刷题量替代理解 |
| PR-02 | MUST 自动记录学习与作答；手写笔记、错因和每日总结均可跳过 |
| PR-03 | MUST 保存草稿与上次位置，并明确展示保存成功或失败 |
| PR-04 | MUST 将原创练习、模拟题、回忆题、正式出版试题分开标识 |
| PR-05 | MUST 保留首次作答、复习、看过答案后作答等不同证据 |
| PR-06 | MUST 使用有来源的讲解、可追溯的答案；AI 输出不能直接成为标准答案 |
| PR-07 | SHOULD 默认展示一项主操作、一小组有限任务；完成后可以结束 |
| PR-08 | MUST 先交付一个完整学习流程；不先建设覆盖全考试的管理系统 |

首个可用版本包括四个导航：今日、学习、练习、回顾；一个学习阶段；选择、简答、代码阅读/填空三种交互；自动记录、间隔复习、简单周总结和备份恢复。

案例材料、图表、子问题作为题目组合建模，首版支持基础展示，后续扩展完整软考案例。首版简答和代码题使用参考要点自评，不做自然语言自动判分，不执行用户代码。

暂缓：公开注册、多用户角色、社区、排行榜、积分、复杂知识图谱、视频托管、实时聊天教师、自动抓取商业题库、在线编译运行、自适应记忆算法、全自动 AI 判卷。

## 3. SDD 开发流程

过程参考 [GitHub Spec Kit](https://github.com/github/spec-kit)。本项目不依赖特定工具命令名称或版本；接入工具时以安装版本的官方说明为准。

每个 feature 形成以下四类文件；同一文件随迭代更新，不反复创建重复版本：

| 产物 | 必须回答的问题 |
| --- | --- |
| `spec.md` | 谁遇到什么问题、范围是什么、必须怎样表现、如何验收 |
| `plan.md` | 如何实现、数据如何存取、采用什么最小方案、关键取舍是什么 |
| `tasks.md` | 按可运行的用户流程拆成任务；每项引用需求和验收编号 |
| `verification.md` | 实际完成了什么检查、结果、证据位置、剩余限制 |

工作顺序：规格 → 澄清实际阻塞项 → 技术方案 → 任务 → 一致性审查 → 实现与必要测试 → 对照验收 → 修订。用户授权某 feature 实现后，正常实现和修复持续执行；不为每个小任务重复申请批准。

文档目录约定为未来的 `specs/<feature-id>/`。本轮只交付总体规范，不创建空的 feature 文件或应用骨架。

编码前门槛：验收条件可观察；范围边界明确；当前实现所需的高影响歧义已消除；内容依赖已准备；没有相互冲突的需求。考试日期等不阻塞本地学习闭环的事项允许保持未定。

范围变更先修改 spec，并同步 plan、tasks、验收；小幅文字修正无需重跑整套流程。修复缺陷先复现，补充相关回归检查，再实施最小修复。不以编写文档数量作为进度。

总体规范是跨 feature 的约束；feature 可细化但不能默默改写它。约束变更必须在总体规范和修订记录中同步说明。仅在用户明确要求时提交 Git 或发布服务。

## 4. 用户流程与功能需求

| ID | 功能与行为 |
| --- | --- |
| FR-01 | 首次进入只需选择本次时长；默认 25 分钟，可选 10/25/45；目标日期和选考语言可跳过 |
| FR-02 | 今日显示有限任务、预计用时和开始按钮；有未完成会话时优先提供继续 |
| FR-03 | 学习页包含目标、先修提示、通俗解释、已知语言示例、易错点、练习与来源 |
| FR-04 | 用户可跳过讲解直接尝试练习；跳过阅读不自动记为已经掌握 |
| FR-05 | 选择题先选后提交；提交前可修改；提交后展示答案及逐项解释 |
| FR-06 | 简答/代码题提交原答案后显示参考要点，逐项选择满足/部分满足/未满足并确认自评；原提交不可覆盖，改答生成新的 Attempt |
| FR-07 | 用户可主动查看答案，但该次作答标记为 assisted，不作为独立掌握证据 |
| FR-08 | 错题及用户标记“不确定”的正确题进入复习；错因记录可跳过 |
| FR-09 | 笔记绑定单元或题目；自由文本即可，不建设复杂文档编辑器 |
| FR-10 | 每周及每个单元可查看统计、薄弱项和最多 3 个下一步行动 |
| FR-11 | 显示资料来源和内容状态；有争议或被撤回题目不进入推荐练习 |
| FR-12 | 草稿、作答与学习位置持久保存；支持整包备份、校验和恢复 |
| FR-13 | 案例材料保持上下文，按子问题保存答案；不可将孤立子题当成完整案例 |
| FR-14 | 后续整卷模式隐藏即时解析，按年份/批次及当期规则计时；不混入基础原创题 |

学习完成有两个独立信号：用户确认读完记为 viewed；单元指定的 checkpoint_question_ids 全部有未看本次答案的通过记录时显示 checked，否则做过检查后显示 needs_practice。checked 只是已通过当前检查，不承诺长期掌握。主观自评结果始终标识 self-rated。

自动推荐的先修满足条件是所有 prerequisite_ids 对应单元均为 checked；用户可主动确认跳过某项先修并记录 prerequisite_override，不改变该单元的真实学习/测验状态。单纯点开或读完不自动满足先修。未满足时仍可主动浏览，并显示先修提示。

## 5. 今日任务与复习规则

### 5.1 今日任务生成

MUST 使用确定性的初版规则，避免黑盒推荐。打开已有会话直接继续；创建新会话时读取当前内容状态、复习队列和学习位置。

1. 按本次时长预留约 40% 给到期复习；优先更早到期，同日到期按 ID 稳定排序。仅选 active 且 reviewed 的内容。
2. 剩余时间安排当前未完成单元的一个小节与关联练习。讲解已完成的，直接安排练习；无可用新内容时使用已学单元的其他题。
3. 总预计时长不超过预算；最小可用任务也超预算时展示其用时，由用户选择开始，不暗中塞入任务。
4. 到期复习的预计总用时超过当次预算时，本次暂停学新；只取预算内复习，剩余条目保留原到期日期。用户可主动转去学习页。
5. 首次没有复习时可把预算用于学新；没有可用任务时说明原因并提供浏览已学内容入口。

默认用时仅是内容作者估计，不是能力评价。不得为凑满时间强塞未满足先修的单元。会话开始后任务顺序保持稳定，内容被撤回的除外。

### 5.2 复习状态与证据

复习记录按题目版本关联，状态为 none、scheduled、low_frequency、suspended。初版间隔为 1、3、7、14 天；这是启发式规则，不是精确遗忘曲线。

| 事件 | 行为 |
| --- | --- |
| 尚无复习记录，首次独立正确且确定 | 创建 scheduled，成功计数为零，3 天后到期；首次正确不等于无需复习 |
| 首次独立做错，或正确但标记不确定 | 进入 scheduled，成功计数归零，次日到期 |
| 到期后独立答对且非不确定 | 成功计数加一；第一次成功后 3 天、第二次后 7 天、第三次及以后 14 天再练 |
| 到期复习失败/不确定 | 成功计数归零，次日到期，回到 scheduled |
| 至少两次合格的跨日复习成功 | 转为 low_frequency，继续按上述间隔复习；历史错题不删除 |
| 同日重复、提前练习或 assisted 作答 | 保留作答历史，不增加成功计数、不推迟当前到期日；独立失败则重置为次日到期 |
| 尚无复习记录，先看答案或 assisted 作答 | 创建 scheduled，成功计数为零，次日到期；不把 assisted 当作一次独立失败 |
| 内容争议、撤回或影响答案的实质变更 | 置为 suspended，解释原因；修订审核后重新安排，不计为学习者做错 |

每题每个本地自然日最多产生一次合格成功；日期按 Asia/Shanghai，时间戳持久化使用 UTC。刷新、重试提交不能重复计数。低频复习中再次做错，回到 scheduled。

主观题需要确认自评后才更新复习；所有必需要点满足且没有“不确定”才算通过。自评是学习辅助证据，不是正式阅卷成绩。未自评的提交进入 pending_assessment，不当作正确或错误。

assisted 的判断范围是本次提交前主动揭示答案，或同一本地自然日较早已经见过该题答案；正常提交后的解析不反过来污染刚提交的 Attempt。必须立即持久化答案揭示时间，即使没有提交也要记录。跨日独立复习允许以前学过解析，否则错题永远无法获得复习成功证据。首次独立正确率额外要求此前从未见过该题答案。

自评延后确认以 submitted_at 所属日期计算学习证据与间隔；不得因多日后补自评把记忆间隔顺延。如果计算出的 due_date 已过去，则保持到期。迟到自评按该题已确认作答的提交时间顺序重新计算复习状态，避免覆盖更新的失败记录。

## 6. 统计与总结口径

| 指标 | 定义 |
| --- | --- |
| 首次独立正确率 | 仅 single_choice；每题当前兼容版本的首次未看答案提交，且此前未看过该题答案；正确数/有评分的题数 |
| 复习正确率 | 仅 single_choice；到期复习中已评分、非 assisted 提交的正确数/对应提交数 |
| 内容覆盖 | 已查看单元数、已练习单元数分别展示；不推算全科通过率 |
| 主观表现 | 已完成自评的小问数及要点覆盖；与选择题正确率分开 |
| 当前待复习 | active 且 reviewed 内容中已到期但尚未完成的题数 |

同一题反复做对不增加首次正确题数。主动看答案后再答，不补记首次独立正确率。被撤回题保留历史，但从当前有效统计分母中移除并显示影响数量。

一个知识点少于 5 道不同的已评分独立选择题时标记“证据较少”，仍展示分子/分母，不排名为最弱或最强。薄弱项先看有足够证据且首次错误比例高的知识点；同等时优先当前阶段，最后按 ID 排序。没有足够数据时推荐完成当前单元，不制造诊断。首阶段每单元只有 4 道选择题，因此默认不进行单元强弱排名；可展示真实错题与待办，不为产生排名凑题。

周总结按本地周一至周日，当前周标注未结束。展示完成范围、首次与复习表现、尚未解决的错因和最多 3 项建议；无数据时显示空状态。MUST 不生成“预计通过概率”。计时作为辅助信息，首版以完成项为主要指标，不把页面打开时长当作有效学习时长。

## 7. 内容与数据契约

本节描述概念实体，不要求分别建立同名表；实现时保持最少必要结构。

| 实体 | 核心字段 |
| --- | --- |
| ContentPack | `id`, `version`, `title`, `scope`, `source_ids`, `unit_ids` |
| Unit | `id`, `version`, `title`, `objectives`, `prerequisite_ids`, `checkpoint_question_ids`, `lesson_path`, `estimated_minutes`, `source_ids`, `review_status`, `availability` |
| Question | `id`, `version`, `unit_id`, `type`, `origin_kind`, `prompt`, `material_id`, `options`, `answer`, `rubric`, `explanation`, `source_ids`, `review_status`, `availability` |
| Material | `id`, `version`, `body`, `assets`；用于一个案例的共享文字、图表、代码 |
| Source | `id`, `title`, `url_or_reference`, `locator`, `accessed_on`, `usage_note` |
| Attempt | `id`, `submission_key`, `question_id`, `question_version`, `session_id`, `mode`, `answer`, `assisted`, `uncertain`, `result`, `assessment_method`, `rubric_ratings`, `submitted_at`, `assessed_at` |
| Review | `question_id`, `question_version`, `status`, `success_count`, `due_date`, `last_success_date` |
| QuestionExposure | `question_id`, `first_revealed_at`, `last_revealed_at`；跨题目版本保留 |
| UnitProgress | `unit_id`, `viewed_at`, `checkpoint_result`, `prerequisite_override` |
| LearningSession | `id`, `budget_minutes`, `task_ids`, `cursor`, `drafts`, `started_at`, `completed_at` |
| Note | `id`, `unit_id` 或 `question_id`, `text`, `updated_at` |

`type` 为 single_choice、short_answer、code_fill。single_choice 的 answer 使用稳定 option ID；short_answer/code_fill 使用 rubric 和参考答案，自评为初版默认。`mode` 为 practice、review、exam；`origin_kind` 为 original、mock、recalled、published_exam。

Question.answer 是参考答案；Attempt.answer 是用户的原始作答。选择题作答保存 option ID；简答保存文本；代码题保存按 blank ID 对应的填空值和独立 explanation 文本。rubric 每个要点有稳定 ID 与语义要求，rubric_ratings 逐项记录自评，避免仅存总分而丢失依据。

`review_status` 为 draft、reviewed、disputed；`availability` 为 active、withdrawn。只有 reviewed + active 可以进入常规练习；draft 可在内容预览明确标识，不参与学习统计。reviewed 表示已经记录来源核验和推导检查，不得暗示经过考试机构认证或独立专家审定。

正文采用 Markdown，题目与元数据采用 JSON，图像随内容包保存并关联出处；首版人工维护，暂不开发管理后台。字段可按题型缺省，但题型必需字段不可缺失。每次发布必须校验引用、唯一 ID、图片、唯一正确选项、评分要点和版本。

修改文字排版保留答案兼容关系；题干条件、正确答案、要点改变时提升题目版本，旧 Attempt 保持不可覆盖，重新审核并使旧掌握证据失效。新版本重新复习，但不能再次当成从未见过的独立首答；总结显示“修订后练习”。

## 8. 首版技术边界

推荐默认方案：Python + FastAPI + Jinja2 + 少量 JavaScript + SQLite，一个应用进程、单用户、本地运行。模板能力与单文件数据存储符合当前规模，不需要先拆前后端服务。[FastAPI templates](https://fastapi.tiangolo.com/advanced/templates/)、[SQLite 使用场景](https://www.sqlite.org/whentouse.html)

此为待 feature plan 落实的技术建议，不是已安装依赖。具体版本在实现时选择受支持版本并锁定。用户熟悉 C# 也可改用 ASP.NET Core，但首版只选一套服务端技术。

首版默认只绑定本机；数据以应用数据库为准，浏览器草稿是临时恢复辅助，不是第二套永久记录。手机同进度访问需要同一个可达服务及访问控制，在后续阶段实现；PWA 安装不自动带来同步和离线能力。

保存使用事务；一次提交具备幂等键。自动保存失败展示待保存状态，允许重试；不得在服务未确认时显示已保存。恢复备份前验证结构和内容版本、显示摘要并保留当前备份；首版只支持整包替换，不进行多端合并。

备份包含内容包版本、已引用的内容快照、草稿、作答、复习与笔记，避免仅备份进度却丢失对应题目。恢复后的统计结果和到期日期应保持一致。

笔记与题目 Markdown 渲染必须禁用或净化脚本/原始 HTML；答案文本不可直接解释执行。涉及公网或跨设备时再补充认证、传输与部署规范，未完成前不公开服务。

## 9. 验收用例

| ID | Given / When / Then |
| --- | --- |
| AC-01 | 没有记录的新用户选择 10 分钟 → 开始 → 获得预算内的首个可用基础任务；不必填写考试日期 |
| AC-02 | 简答写到一半且保存已确认 → 关闭再打开 → 返回原题并恢复同一草稿 |
| AC-03 | 选择题选 A 再改 B → 提交 → 只按 B 产生一次评分和记录 |
| AC-04 | 同一提交因网络重试发送两次 → 服务处理 → 仅有一个 Attempt 与一次复习状态变化 |
| AC-05 | 错题提交后查看解析 → 当天做对 → 仍保留次日复习，不升级为低频 |
| AC-06 | 次日及后续到期日独立正确 → 两次合格成功 → 状态 low_frequency，下一次间隔 7 天 |
| AC-07 | low_frequency 中独立失败 → 提交 → 清零成功次数，次日复习 |
| AC-08 | 先点看答案再提交正确答案 → 总结 → 标记 assisted，不增加首次独立正确分子/分母 |
| AC-09 | 主观答案与参考措辞不同 → 用户按要点确认满足 → 保存 self-rated 结果，不按字符串误判 |
| AC-10 | 主观题已提交未自评 → 离开 → 保留 pending_assessment，不计作错误或正确 |
| AC-11 | 题目变为 disputed → 生成新任务 → 不选该题，历史记录保留 |
| AC-12 | 题目答案发生实质修订 → 发布新版 → 旧作答不变、新版重新审核、旧掌握证据失效 |
| AC-13 | 多天没学且积压超预算 → 打开今日 → 只安排预算内复习，未选题仍保留原到期日 |
| AC-14 | 同一道题做对 10 次 → 查看统计 → 首次独立统计最多计一次，复习统计另列 |
| AC-15 | 知识点仅有 2 道独立题记录 → 查看总结 → 展示 1/2 等原始证据并标注证据较少 |
| AC-16 | 备份后在空数据库恢复 → 查看 → 草稿、历史、笔记、版本、复习日期一致 |
| AC-17 | 输入损坏或不支持版本的备份 → 恢复 → 报告校验失败，原数据库保持完整 |
| AC-18 | 两个案例小问共享图表 → 切换小问 → 上下文可访问，草稿彼此独立 |
| AC-19 | 保存时服务不可达 → 输入 → 页面明确显示未保存；服务恢复后可重试 |
| AC-20 | 笔记包含脚本或 HTML → 展示 → 按安全文本/净化内容呈现，不执行 |
| AC-21 | 前置单元未 checked → 浏览后续单元 → 显示缺失先修；仅浏览不改变推荐资格；明确选择跳过后记录 override |
| AC-22 | 正式模考阶段存在草稿 → 时间耗尽 → 按当期试卷规则结束作答并保存；统一交卷后才显示解析 |
| AC-23 | 首次独立答对且确定 → 提交 → 3 天后安排复习，成功计数仍为零 |
| AC-24 | 看答案但不提交就关闭 → 当天重新打开再作答 → assisted；后续跨日盲答可成为复习证据但不再成为首次独立答题 |
| AC-25 | 昨天主观题未自评、今天已提交失败记录 → 补昨天的通过自评 → 按提交顺序重算，保留今天失败后的次日到期状态 |

测试层次：复习日期、统计口径、版本切换用确定性测试；提交与恢复用集成测试；学习—作答—复习—回顾使用少量端到端测试；阅读清晰度、键盘操作、图表缩放、手机布局人工验收。测试数据使用小型原创题库，不上传受限试题。

每次实现按当前阶段执行适用检查，AC-22 属于后续模考阶段，不要求首版提前实现。实现前在 feature 规格中细化该阶段用例。

## 10. 完成标准与已知限制

一个 feature 完成必须同时满足：规格行为已实现；适用验收用例通过；内容来源与核验记录齐全；未通过事项明确列出；用户可以按简单步骤启动和使用；没有为了未来需求引入额外系统。

题目审核与产品试用是不同工作：自动结构校验不能证明答案正确；同一作者自审不能冒充独立复核；程序测试不能证明小白能看懂。阶段评审分别记录这些证据。

本轮开发规范完成不等于应用验收通过，不得将本文件中的目标指标当作实测结果。
