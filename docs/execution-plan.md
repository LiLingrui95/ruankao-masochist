# 分阶段执行计划

版本：1.1 · 2026-09-24 · 状态：P0 内容制作与 P1 简要平台已交付；真实用户试读和使用反馈待完成。实现范围与检查证据见 [verification](../specs/001-study-session/verification.md)。

## 1. 先准备小包内容，再让软件服务真实学习

执行顺序：P0 内容试点 → P1 可用学习流程 → P2 间隔复习与基础阶段补齐 → P3 考试专题 → P4 模考 → P5 按需跨设备。

每阶段以退出条件推进，不把未经试读的课程全部批量生产，也不先开发通用题库平台。每天可投入时间与考试日期未定，因此下表不使用虚假的精确工期。

开发与学习分开计时：用户不需要为了使用平台先学完 FastAPI、数据库开发或前端框架。先读课程、练题、反馈困难；应用由后续编码任务实现。

## 2. 阶段与验收

| 阶段 | 交付 | 前置条件 | 退出条件 |
| --- | --- | --- | --- |
| P0 内容试点 | CSF-01/02/03，3 单元、18 原创题；来源与核验记录；学习页/作答页流程说明 | 本轮规范；能访问必要原始资料 | 题目来源、答案、先修、目标映射完成检查；至少一次实际试读，或明确标记试读待验证 |
| P1 可用学习流程 | 本地单用户网页；今日、学习、练习、回顾；三类作答、自评、草稿、历史、笔记、备份 | P0 技术核验通过；对应 feature spec/plan/tasks 就绪 | 完成“打开—学习—作答—反馈—关闭—继续”；重启与恢复不丢已确认数据 |
| P2 复习闭环 | 固定间隔复习、有限今日队列、周总结；补齐 8 单元、48 原创题 | P1；已验证内容生产流程 | 到期、同日重做、不确定、自评、版本变化均符合规范；完成一周实际使用观察 |
| P3 考试专题 | 首个考试相关专题包，建议数据库基础与设计；完整案例上下文；C/Java/C++ 过渡内容按路径推进 | P2；先修内容足够 | 用户能完成一组从概念到案例的练习；相关真题出处逐题核验 |
| P4 真题与模考 | 年份/批次试卷、当期规则、计时、答题卡、交卷复盘；两个科目分别统计 | 已具备足够知识覆盖和完整已核验试卷 | 至少一套完整模拟流程验收；计时、保存、子题/选做关系正确；复盘能返回具体知识点 |
| P5 按需增强 | 手机同进度访问、访问控制、部署、可选 PWA 安装；AI 解释仅作为独立可选 feature | 已证明使用频率与跨设备需求 | 两设备读取同一记录；访问控制、失败恢复通过；不要求实现离线写入合并 |

P1 以基础导航承载历史记录，P2 才提供完整阶段总结。P1 的错题先可在历史中筛选，P2 实现调度；不得将 P1 宣称为完整复习系统。

P0 的“试读待验证”不是教学验收通过。可在标注该限制的前提下继续 P1 小范围实现，不能据此扩大全考纲内容生产。真实试读是扩展 P2 内容的条件。

| P1-T02 | 选择题、简答与代码题作答；参考答案揭示与自评 | FR-05/06/07 | 三类题均能独立提交、反馈、保存历史 |
| P1-T03 | 持久化会话、位置、草稿、作答和笔记；提交幂等 | FR-09/12 | 关闭/重开、重复提交、服务中断检查 |
| P1-T04 | 今日继续入口、简单记录页、整包备份与恢复 | FR-01/02/12 | 空用户可开始，老用户能继续，恢复结果一致 |
| P1-T05 | 执行验收并编写 verification；用三节内容实际学习 | 完成标准 | 检查结果与试用记录；失败项有修复或明确延期 |

P1 应按最小用户流程逐步打通：先一个单元加载并能做一道题，再补另外两种题型与可靠保存。避免先写完全部数据库、再写全部页面、最后才发现内容不适配。

P1 的今日安排仅实现时长预算、当前单元和先修约束；P2 再接入到期复习分配规则。统计、自评与答案揭示所需的原始记录必须从 P1 开始保存，不能等到 P2 才补造历史。

## 5. 学习内容路径与软件阶段的区别

P0—P5 是建设阶段，CSF-01 等是课程单元，两者不能混用。建议的课程推进如下，具体节奏由练习证据调整：

| 学习阶段 | 内容 | 选择理由与边界 |
| --- | --- | --- |
| L0 基础桥接 | 本文配套 8 单元 | 先建立术语和程序执行模型；熟悉的单元可以诊断后跳读 |
| L1 数据结构与 C | 数组、栈队列、链表、查找排序、基础复杂度；C 函数/数组/指针按需引入 | 将已有编程经验连接到考试代码；不一次塞入高级算法 |
| L2 数据库与设计 | 表、键、关系、SQL、函数依赖、范式、ER 与关系转换 | 场景明确，便于从基础练习逐步进入案例；第一批可仅覆盖表、键、简单 SQL |
| L3 软件工程与建模 | 生命周期、需求、DFD、UML；Java/C++ 基础与设计模式穿插 | 用一个小系统贯穿概念，避免只背图形和术语 |
| L4 系统知识 | 组成原理、操作系统、网络与安全；补齐标准、知识产权、专业英语 | 基于 L0 继续拓展；基础知识练习与应用技术练习并行 |
| L5 综合训练 | 算法策略补齐、跨专题练习、近年核验真题、整卷模拟 | 保留少量未练过的完整试卷；已背熟题目不能当作预测成绩 |

这是一条适合当前基础的初始教学路线，不是官方推荐顺序，也不是章节权重结论。L1/L2 后即可开始少量对应案例，无需等全部基础学完。薄弱专题可以回补，整体范围最终需对照当期考纲核验。

编程方向：先保留 Python/C# 解释，再引入 C 阅读；进入面向对象考试题前选定 Java 或 C++，内容推荐只推选定方向，但保留另一方向的浏览入口。未选择时不自动推荐选考题。

## 6. 试用后的决策规则

- 经常不知道今天学什么：优化今日任务，不增加日历规划页面。
- 讲解看不懂：补术语、例子和先修提示；暂缓新章节扩充。
- 经常猜对或记住选项：增加不确定标记和跨题型迁移练习。
- 主观题自评很困难：先修评分要点与对照展示，不直接上 AI 自动判分。
- 错题积压：减少新题，保留真实积压但分次呈现，不伪造已完成。
- 数据有丢失：停止功能扩展，先修保存/恢复并回归验证。
- 真实出现手机使用需求：进入 P5；如果没有，继续保持本地单用户方案。

## 7. 本轮交付边界

已交付总体开发规范、执行计划、首阶段课程/题库设计、一个完整编辑样稿及六道配套题、自审记录。

未交付应用代码、可运行平台、完整 48 题内容包、真题数据、独立专家审校、用户试读结果。后续执行不能把这些未完成事项标记为完成。
