## 2. 第二轮：规则与数据可实现性

| 问题 | 修订 | 对应位置 |
| --- | --- | --- |
| 只让错题进入复习，首次全答对的单元永远没有跨日证据 | 首次独立正确且确定安排 3 天后复习，首次看答案安排次日复习 | 开发规范 5.2，AC-23 |
| 看答案不提交，只有 Attempt 无法追踪污染 | 增加 QuestionExposure，立即记录答案揭示；区分当日 assisted 与跨日独立复习 | 开发规范 5.2/7，AC-24 |
| 自评时查看参考答案会被误记为当次 assisted | 以提交前揭示判断；正常提交后看参考不反向改变该次记录 | 开发规范 5.2 |
| 主观提交后再改原答案可能伪造能力证据 | 原提交不可覆盖；改答产生新的 Attempt | FR-06 |
| 延迟自评可能覆盖后来的失败并错误延期 | 以提交时间排序重算，保留最新行为结果，过期日期保持到期 | 开发规范 5.2，AC-25 |
| 先修“满足”与读完/做对含义不明确 | 指定 checkpoint_question_ids；checked 或明确跳过先修才满足自动推荐条件 | 开发规范 4/7，AC-21 |
| 混合选择题评分与主观自评产生误导性正确率 | 首次与复习正确率仅统计选择题，主观单独报告要点覆盖 | 开发规范 6 |
| 每单元仅 4 道选择题，却要求至少 5 题才能排名 | 明确首阶段默认不做强弱排名，展示原始证据和待办即可 | 开发规范 6 |
| 题目修订覆盖旧答案与复习证据 | 保留版本与历史，实质修订重新审核，不再算全新首次答题 | 开发规范 7，AC-12 |
| 只备份学习记录可能恢复不到相应题目 | 备份含关联内容快照与版本；恢复先校验，整包替换并保留恢复前备份 | 开发规范 8，AC-16/17 |
| P1/P2 功能边界不清 | P1 保留原始记录与简单预算；P2 才启用复习队列和完整总结 | 执行计划 2/3 |
| CSF-01-Q06 原题干未写明变量与解释要求，评分却要求 | 把“使用已有数量变量、说明计算依据”写入题干，允许等价表达式 | 内容规范 Q06 |
| C# 示例输出来源尚未补全 | 查阅 Microsoft Learn 的 WriteLine 与 assignment 文档，补入来源记录 | 内容规范来源记录 |
