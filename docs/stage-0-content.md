## 1. 为什么先做这个阶段

用户已经学过 Python、C#，没有必要按完全不会写代码处理；但也不能直接假定理解内存、进程、二进制、算法复杂度。先用已有语言经验解释基础概念，再进入数据库、操作系统和考试案例。

这个阶段是 CS foundation，不是官方考纲的独立章节，也不是完整备考课程。首阶段题目全部为原创基础练习，不称真题，不用于模拟考试估分。

目标：能把一个简单程序的输入、处理、输出说清楚；能逐步跟踪变量；区分列表/数组的索引与元素；理解 bit、byte 和简单二进制；区分 CPU、内存、持久存储与操作系统的职责；对常数、线性、二次增长有基本直觉；能在 Python/C# 的帮助下阅读少量 C 语句。

## 3. 教学与题目写作规范

每个单元 MUST 包含以下结构：

1. 不超过 3 个可以观察的学习目标。
2. 必要先修与一个自查问题；不熟悉时有返回链接。
3. 一个熟悉的场景与通俗解释。
4. 精确术语，首次给出中文解释和 English term。
5. 至少一个逐步推导例子；只展示结论不合格。
6. 常见误区及反例。
7. 关联练习、答案与错误选项解释。
8. 来源、适用范围和编辑核验记录。

术语不能循环解释。类比之后必须指出边界，例如“内存像工作台”只解释工作数据与持久保存的区别，不能推出所有内存都具有相同速度、容量或持久性。

Python/C# 示例是理解入口；涉及语言差异必须说明条件，例如 Python `/` 与 C# 整数操作数的 `/` 行为不同，不能把一种语言的语义直接搬到另一种语言。[Python 数值运算说明](https://docs.python.org/3/tutorial/introduction.html)、[C# arithmetic operators](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/operators/arithmetic-operators)

每道题 MUST 有唯一 ID、单元/目标映射、题型、来源类型、完整题干、参考答案、推导、误区解释、核验状态。所有选项具有稳定英文 ID，不依赖当前显示序号。主观题要点应描述语义，不要求与参考答案逐字一致。

同一道原题只换数字可作为重复练习，不自动声称是迁移题；真正的迁移检查需改变场景或表达，并验证仍考同一个概念。

### 学习目标

- 能在一个简单场景中指出输入、处理、输出。
- 能区分赋值、计算和输出。
- 能读懂一个顺序执行的小程序并解释计算结果。

### 从买东西开始

买 3 本笔记本，每本 12 元，应该支付多少？你需要知道单价和数量，按规则相乘，得到 36 元。

可以用三个词描述这个过程：Input 是计算所需的数据；Processing 是对数据执行的步骤；Output 是希望得到的结果。程序是表达这些步骤的指令，数据是步骤处理的对象。

这里的“输入”采用问题建模的含义。数值可以来自用户键盘、文件，也可以先写在示例代码里；“程序使用了输入数据”不等于“调用了 input()”。本节不要求掌握键盘输入函数。

```python
unit_price = 12
quantity = 3
total = unit_price * quantity
print(total)
```

| 执行完的语句 | 当前相关值 | 是否向终端显示结果 |
| --- | --- | --- |
| `unit_price = 12` | `unit_price` 为 12 | 否 |
| `quantity = 3` | 再增加 `quantity`，值为 3 | 否 |
| `total = unit_price * quantity` | `total` 为 36 | 否 |
| `print(total)` | 值仍为 36 | 是，显示 36 |

`=` 在这里是 Assignment：计算右侧的值，再把结果绑定到左侧变量名。本节可先把变量理解为用于访问值的名字。赋值本身与显示结果是两件事。

在这段 Python 脚本中，前三行不会主动显示数值，最后一行 `print()` 才显示 36。Python 交互式解释器会显示某些表达式的结果，但不能据此认为脚本中的每条赋值都会打印输出。

对照你接触过的 C#，下面这一段可以放在有效的 C# 程序体中理解：

```csharp
int unitPrice = 12;
int quantity = 3;
int total = unitPrice * quantity;
System.Console.WriteLine(total);
```

两段示例完成同一个整数计算；类型声明、语句结束和输出写法不同。本节只比较这段代码，不推出两种语言所有运算行为都相同。

### 两个容易混淆的地方

- `total = unit_price * quantity` 计算并保存当前结果；显示结果需要输出操作。
- 一道题里的“输出”可以是返回给调用者的结果或写入文件的数据；本节示例特指终端显示，不把输出等同于打印。

### CSF-01-Q01 · single_choice · 输入、处理、输出

在“使用单价和数量计算总价”的模型中，哪一项属于处理步骤？

- A. 单价 12 元。
- B. 数量 3。
- C. 将单价乘以数量。
- D. 得到总价 36 元。

答案：C。A、B 是输入数据，C 是运算规则，D 是结果。这里讨论问题模型，不限定数据从键盘进入。来源：CSF-01 原创教学模型。

### CSF-01-Q02 · single_choice · 赋值和显示

把下面两行保存为 Python 脚本并运行，没有其他语句。终端会显示什么？

```python
unit_price = 12
total = unit_price * 3
```

- A. 12。
- B. 36。
- C. 先显示 12，再显示 36。
- D. 不显示这两个数值。

答案：D。两行分别完成赋值、计算并赋值，没有调用输出语句；A/B/C 都把计算或赋值误认为打印。题干限定脚本，排除交互式显示差异。来源：SRC-PY-INTRO。

### CSF-01-Q03 · single_choice · 顺序计算

下列 Python 脚本显示什么？

```python
unit_price = 7
quantity = 4
total = unit_price * quantity
print(total)
```

- A. 11。
- B. 28。
- C. 7。
- D. 4。

答案：B。7 × 4 = 28，print 显示 total 当前值。A 错将乘法当加法，C/D 只取了一个输入。来源：SRC-PY-INTRO。

### CSF-01-Q04 · single_choice · 结果与输入

一个程序接收矩形的长和宽，计算并返回面积，不在终端打印。以下描述正确的是哪项？

- A. 没有 print，因此一定没有输出结果。
- B. 面积是输入，长和宽是输出。
- C. 长和宽是输入，计算面积是处理，返回的面积是输出。
- D. 输入数据只能来自键盘，因此这个描述不成立。

答案：C。输出不必是终端打印；A 把示例输出方式当作输出定义，B 颠倒输入输出，D 错把输入限于键盘。来源：CSF-01 原创教学模型。

### CSF-01-Q05 · short_answer · 描述计算过程

某停车场按整小时收费，不考虑优惠与不足一小时的情况。给定停车小时数和每小时价格，请用自己的话说明输入、处理、输出。

参考答案：输入为停车小时数和每小时价格；处理为两者相乘；输出为应付金额。

评分要点：R1 明确两个输入；R2 明确相乘规则；R3 明确输出金额。每项满足/部分满足/未满足；只有三项全部满足才记为本次检查通过，不要求相同措辞。来源：CSF-01 原创迁移场景。

### CSF-01-Q06 · code_fill · 补全表达式

Python 脚本需要计算 5 件商品的总价，每件 9 元。使用已有的数量变量补全空白，写出最后显示的数值，并简述计算依据。

```python
unit_price = 9
quantity = 5
total = unit_price * ______
print(total)
```

参考填写：`quantity`；输出：`45`。

评分要点：R1 空白位置使用数量变量；R2 输出 45；R3 能说明按“单价 × 数量”计算。题目要求补空并说明结果；界面提供代码空白与说明两个输入区域。

`(quantity)` 等语义等价写法可接受。填写常量 `5` 虽在这组数据上同样得到 45，但未满足题干“使用已有数量变量”的要求，只部分满足 R1；不是数值计算错误。

来源：SRC-PY-INTRO；示例与解析原创。
